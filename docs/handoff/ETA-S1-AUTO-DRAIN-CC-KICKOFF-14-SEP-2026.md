## 2. Why this slice exists

A `bench_window` closing is the only trigger the room tape has, and today it inserts a row into the
legacy `stt_subject_job` table and stops. Nothing drains it. `drainRoomWindow` is only ever called
by two admin-authenticated routes, so **a room transcribes only when a human clicks**. That is the
one missing link between "the job layer shipped" and "the rooms transcribe themselves".

Second, unrelated but batched here because it is four lines: an `emotion_window` job whose every
segment failed records `state: "ok"`. A caught failure that produces success-shaped output is
testing rule 9.

## 3. SETTLED DECISIONS — restated here so you never need the PRD

**D-S1.1 — The auto-drain is a CRON ROUTE, not a hook on window close.** `evaluateWindows` has no
`origin` to give `submitJob`, and the chunk route's tail is the recording critical path. It mirrors
`/api/admin/diarize-windows` exactly.

**D-S1.2 — Actor is `SYSTEM_ACTOR` with `via: "cron"`.** `actorProblem` in `lib/stt/receipt.ts`
already refuses `SYSTEM_ACTOR` on any other via, and refuses `via:"cron"` for any other actor. Use
the exported constant; do not type the string.

**D-S1.3 — Ships DARK behind `ROOM_AUTO_DRAIN_ENABLED`.** Parsed with `parseFlag` from
`lib/flags.ts`. Unset = clean no-op returning `enqueued: 0`. Never read a flag with `=== "1"`.

**D-S1.4 — ONE window per tick, newest first, recency-bounded to 6 hours.**
`AUTO_DRAIN_BATCH_LIMIT` default **1** (env override, integer, clamp 1..10).
`AUTO_DRAIN_MAX_AGE_HOURS` default **6** (env override, integer, clamp 1..48).
Reason, and it is not negotiable: **`route`'s realtime factor on a genuine 900 s window has never
been measured.** One window per five minutes is 288/day, which exceeds what six recording rooms
produce (~216/day), so live traffic keeps up — while the 350.78 h backlog stays untouched. The
backlog is a separate, deliberate build. **Do not order oldest-first and do not raise the cap.**

**D-S1.5 — Zero scored is a failure.** In `lib/jobs/kinds/emotion-window.ts` `finish()`: when
`p.segments.length > 0 && p.scored === 0`, record the window with `state: "failed"` and
`error: "emotion_zero_scored"`, and return a job failure so the runner's attempt counter bounds it.
When `planned === 0` it stays the existing `no_segments` path — that is a legitimate quiet pass.
When `scored > 0` with some failures it stays `"ok"` — partial success is success.

## 7. Tests — these exact properties, and note rule 7

1. Flag off ⇒ `enqueued: 0` and **no** call to `drainRoomWindow`. **Paired, in the same file, with
   flag on ⇒ it does enqueue** — a refusal test that never proves the refusal is not universal is
   the defect testing rule 7 names.
2. The selector excludes: a window older than `AUTO_DRAIN_MAX_AGE_HOURS`; one with
   `grid_aligned = false`; one with a null `room_day_id`. Each exclusion paired with an included
   control row differing only in that field.
3. The cap is respected and ordering is newest-first.
4. Emotion: `planned > 0, scored = 0` ⇒ `state: "failed"` + `emotion_zero_scored`; `planned > 0,
   scored > 0, failed > 0` ⇒ `"ok"`; `planned = 0` ⇒ `no_segments` unchanged.
5. Boundary fixtures are expressed in terms of the constants (`AUTO_DRAIN_MAX_AGE_HOURS`), never
   the numbers those constants happen to produce (rule 10).
