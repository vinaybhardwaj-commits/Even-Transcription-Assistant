# EvenScribe Room Recorder — release notes

Earlier versions are recorded in `docs/BUILD-HISTORY.md`.

- **0.1.42** — Encounter Buddy L2, built from 0.1.41 (buddy/l1-recorder 38c61399, which is not on main yet). A runner inside the app carries 12 s chunks of the tape to newcat's chunk route on the c4 tailnet listener and keeps the live transcript for the page. It exists only on a Mac whose room root holds a private `buddy-runner.json` (base URL and consumer key, mode 0600); without it a consult behaves exactly as in 0.1.41. On `consult_started` it gets a room token (15 min or less), then polls the flags at once, every 60 s, and at each stop. The SEND gate and the DISPLAY gate are separate: chunks go while `live` is true; the window and the page exist only while `window` is true, so a shadow session (live true, window false) sends and shows nothing, and a reply with no `text` is normal. `live` false stops all sending and polling. A `window` true under a killed fleet is counted as a breach and the window stays shut. Audio is read through the 0.1.41 tap into a ring of at most 60 s in memory (oldest frames drop with a gap marker), cut into 12 s 16 kHz mono PCM16 WAV chunks, one in flight per consult, and posted with the envelope in `x-chunk-*` headers. 403, 409 duplicate_seq, 429 and 503 stop the consult for good; 502 and 409 busy are retried twice (1 s, 2 s), then become a gap; audio captured more than 60 s before a send attempt is not sent, and a timeout with no answer is a gap, never a resend. No audio and no text is written to disk; logs hold counts, codes and timings only. The page gains the A2-C2 notice (wording is V's), the live transcript (collapsible), the stale indicator (30 s) and "live transcript off / unavailable"; no question or suggestion field exists. The C8V3-C4 snapshot check is built and tested for L5. The cloud chunk path is byte-identical with the runner on or off.
- **0.1.41** — Encounter Buddy L1, built from 0.1.40 (main c09539f4). The app gains a read-only tap and its own window; there are no models and nothing is sent anywhere. A `consult_started {opaque_id}` command opens a small non-activating panel titled "Encounter Buddy" in the recorder (never in Chrome, never taking focus, close button hides it) showing a local page at `http://127.0.0.1:<port>/encounter/<opaque_id>`: recording (true only with an open session), the microphone state (`authorized`, `denied` or `input_device_not_ready`) shown separately, and the opaque id. `consult_ended` closes it. `buddy_off: true` on `consult_started` (the newcat kill switch) opens no window and serves nothing. The same server, bound to 127.0.0.1 only, serves `GET /tap/pcm?from=&max=` (the current capture's `tape.pcm`, read-only) to a bearer of the per-boot 256-bit token, which sits in `buddy-tap.json` (0600) only while a consult is live and is never logged or put in status.json. The tap writes no audio, opens no second capture and does not touch CoreAudio; the cloud chunks are byte-identical with it on or off. No recording is started, stopped or reconfigured by either command. Also: every device open re-applies the stored input volume (default 1.0 where settable) and logs the value before and after; exact zeros from an authorised, attached microphone for 120 s are logged once as `capture_zero_coreaudio_suspect` (the 15 Oct near-silence was a CoreAudio state problem, cured by restarting coreaudiod); the poll gains `displays_count` (an integer); `FileFleetKeyStore` requires `currentDeviceID`; the rotation wait is cleared after a successful register (FU-RR0140-1).
- **0.1.40** — the fleet device key moves off the login keychain into `fleet-key.json` in the room root (0600, owner-checked, atomic). Cause: the keychain item's partition list held the cdhash of the build that wrote it, so the next build's read raised a prompt nobody could click and blocked the fleet client, the kiosk-health relay and the steward fetch for ever (OPD 6, 13 Oct). The keychain is read at most once, only when the file is absent, non-interactively, on its own thread, with a 5 s deadline; an item only a person could open (or no answer in time) gives a NEW key and a NEW device registration, never the old device id with a new key. The old item is never changed. FleetClient waits at most 10 s for any key load. A rotation is recorded in fleet-key.json (`origin`, `replaces_device_id`) in the same write as the key, so a late or missed rotation never signs for the old device. A register refused with KEY_CONFLICT or REVOKED after a rotation is retried every 900 s, never persisted as a stop, until the server re-keys the install. Built from 0.1.39.
- **0.1.39** — FR-1 C2, built from 0.1.38. status.json gains `last_poll_ok_at`, `last_http` and `last_chunk_uploaded_at`. New `room-recorder probe-helper` (one XPC hello, 3 s, prints `ok <helper version>` or `fail <reason>`). An install with no session re-reads its session and config every 5 minutes and shows `needs_enrol`, instead of parking. A day that never started is retried when the microphone or the device is back in the clinic window (3 per hour). A recording whose tape does not grow for 3 minutes has its capture owner restarted (never the process); state `capture_stalled`, a repeat is flagged in `last_event`. The unreachable `.retired` exit path and its stale comments are gone. A 409 RETIRED still never stops an open recording.
- **0.1.28** — MicModeGuard fixes from the OPD 5 test. tapewriter line-buffers stdout, so guard lines reach tapewriter.log as they happen. A call that outlasts its timeout no longer blocks later calls; the Set has 10 s (reads stay 2 s), a timed-out Set is reported as set "timeout" (not "fail"), and the mode is re-read on a fresh runner afterwards. mic_mode.json and status.json mic_mode now carry set_ms. The 60 s watchdog reads both the preferred and the active mode on a fresh runner each tick and logs one line per tick; any non-zero value is Set to 0 in place (no process restart, last_event "mic_mode_reset", at most one reset per 2 minutes, suppressed resets logged); an unreadable mode (-1) is logged and written as "unreadable". The exit-76 mic-mode restart path is removed (tapewriter, CLI and engine); nothing else used exit 76. Built from 0.1.27.
- **0.1.27** — 0.1.26 plus the 0.1.25 branch, never released: the `self_test` bench command (pinned stimulus pack, gate: refuses while a session is open, outside clinic hours, when not ready or already running; built-in speaker player; local manifest), tape_advancing follows tape.pcm, device_state poll field, and auto-start at clinic open. Auto-start is OFF on every Mac unless an `auto-start-on` file sits beside config.json (the Room Steward owns starts). A build without a pack refuses self_test with pack_missing.
- **0.1.26** — MicModeGuard: on macOS 26 and later the recorder forces Mic Mode to Standard (never Voice Isolation, which gates the room mic to exact zeros) for its own bundle id and its parent id before each capture session starts, through a dlsym'd AVFCapture shim that does nothing when the symbols are missing; a 60 s watchdog re-checks while recording and, if the active mode is not Standard, sets it again and rebuilds the capture session, at most once per 10 minutes. The rebuild is a planned restart: tapewriter finishes the segment and exits 76, and the engine relaunches it at once in the same session without the server (log line "tapewriter planned restart: mic_mode", status.json last_event "mic_mode_restart", never phase failed); a second 76 within 10 minutes in one session takes the normal unexpected-exit path. The relaunch does not wait out the poll back-off when the server is down (the back-off sleeps in 1 s slices and checks the capture process each slice), and last_event is cleared when a new session starts. Built from 0.1.24; the unreleased 0.1.25 branch must be renumbered above 0.1.26.
- **0.1.24** — 0.1.23's fix, corrected: `RoomSubprocess` no longer sets a `Process` stream after `run()`, which Foundation refuses with `task already launched` — 0.1.23 died on that at every launch.
- **0.1.23** — WITHDRAWN 17 Sep, never shipped past Home Office: crashed at launch (see 0.1.24). Do not use `Foundation.Pipe` for poll helpers or ffmpeg stderr (`RoomSubprocess` temp files). The live leak was `MachineFacts.runTool` three times per 1.5 s poll while recording, not only failed piece writes.
- **0.1.22** — three operator verbs from the desk: check_update_now, report_diag (redacted, never a secret) and restart_engine; a Mac may pin its own channel in config.json and says so in its heartbeat; the heartbeat also carries clip count and time since the last audible frame.
- **0.1.21** — set_audio_input: switch the recording device and set input volume from the desk; unknown command kinds are ignored, never fatal.
- **0.1.20** — peak and exact-zero measurement; input-device list; server may move a Mac to stable; update check at every session end; incremental level reads; one session-read log line; rescue sweeps staging.
- **0.1.19** — no functional change; first release offered to a clinic Mac through the leaf-only self-update path.
- **0.1.18** — self-update verifier no longer requires the Mac to trust the signing certificate; leaf pin unchanged.
