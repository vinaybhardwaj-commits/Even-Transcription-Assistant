# diag-rig (SELFTEST digital path, build 1) — diar-lab, Fable order S1 (26 Sep 2026)
Stdlib-only. `python3 diagrig.py generate|inject|score|run|proof`. Tests: `python3 -B -W error::ResourceWarning -m unittest test_diagrig` (~12 s, needs ffmpeg).
- **generate**: WAV (16 kHz mono int16) + `<id>.truth.json` per stimulus + `suite.json` (sha of every file, phrase-set sha). Tones (sweeps + 250/1000/4000 Hz at -60/-40/-20/-6 dBFS), silence patterns (exact zero, dither floors), the canary word x3, 2-3 speaker dialogues (en/hi/kn/te/ta, Hinglish, Kanglish), noise beds (fan/ac_hum/babble/door/phone_ring) at +20..-5 dB SNR. Suites: smoke, nightly, full.
- **TTS**: `--tts elevenlabs` (key works for speech only: it lacks voices_read/user_read, so /v1/voices and /v1/user are NEVER called; fixed premade voice ids in `tts.VOICES` (S1 Rachel verified, S2-S5 UNVERIFIED); multilingual_v2 for en/hi/ta and hi-en code-mixed, Google for kn/te/kn-en unless `DIAGRIG_EL_V3_LANGS=kn,te` opts them into eleven_v3 after a 1-line test), `--tts google` (V approved; gcloud token in memory only), `--tts fake` (deterministic pseudo-voice for tests, flagged `synthetic_fallback`, NOT speech). Clips cached by sha256(backend|voice|model|seed|lang|text), never re-synthesised; per-backend char ledger caps the first run at 60,000. Voice names in `tts.VOICES` are UNVERIFIED defaults: check before the first real run (elevenlabs needs a voices.json of stock ids; no cloning).
- **Gates**: the Kanglish list needs V's approval (`phrases.KANGLISH_APPROVED`) before any real-TTS run that includes it; the destination gate is FAIL-CLOSED on the target URL host: only loopback or hosts named in DIAGRIG_ALLOW_HOSTS are accepted (the `--machine` label is normalised and checked too, and anything Mini-like needs DIAGRIG_ALLOW_MINI=1, only after refuter-2 PASS + Fable's word); the diarizer engine needs DIAGRIG_DIARIZE_NOPERSIST_CONFIRMED=1 (UNVERIFIED that /diarize writes no DB rows for encounter_id diagrig-<sid>: confirm first); `run --nightly` refuses outside 23:00-06:00 IST; frozen audio sha is re-checked before every injection.
- **inject**: webm/opus 32k (the production shape) POSTed to `--stt-url` (whisper/router-shaped: transcript_native, dominant_language, segments) and/or `--diarize-url` (/diarize: transcript_segments with speaker). A failed call is a scored miss. Results stay in the 0700 run dir.
- **Commands** also: `budget` (local char ledger, one total across backends vs the 60k cap) and `voices google|elevenlabs` (google: read-only voices:list; elevenlabs: prints the fixed ids, no network).
- **score**: one report (JSON + short text): word hit rate/WER/CER per language, canary hit (mic-selftest's fuzzy matcher), language-ID, speaker-count error + DER, silence detection (reference detector: time-to-detect, false alarms, STT text inside silence), noise robustness deltas. Ids, counts, metrics only; no transcript text. Failures are first-class: every language and the canary carry n_attempted/n_ok/n_failed/n_no_result, failed calls count as misses (hit_rate_incl_failures, canary misses) and the headline line shows target failures. Silence: `rig_selfcheck` (the reference detector on the rig's own wav, NOT a target metric) is reported apart from `target` (STT text / diarizer speech inside silence). Babble beds use other speaker ids and other languages than the scored dialogue (provenance in truth `bed_sources`); the canary has its own bucket. Production path is scored; offline models would be extra `shadow` engines.
- **proof**: queue001 timing proof (tone at t=100 s through the webm encode, ±50 ms).
NOT built yet: acoustic runner (Home Office), remote transport for non-box machines (W22 capture_driver variant), shadow engine columns, nightly cron/bus post. Nothing here has run against a production endpoint.
