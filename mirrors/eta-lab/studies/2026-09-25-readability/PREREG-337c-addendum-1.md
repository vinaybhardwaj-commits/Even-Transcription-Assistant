# Ruling 337c: readability flag, PRE-REGISTRATION ADDENDUM 1 (split-speaker, 25 Sep 2026, ~08:30 IST; BEFORE any label exists)
Origin: eta-refuter #1909 / #1914 (PASS-WITH-FIXES) and #1900. `PREREG-337c.md` (4fc8a3c) and the frozen sample `sample200_ids.json` (67256af) are unchanged; this changes only how the sample is labelled and how the result may be used.

1. **Blind, shuffled sheet.** The first sheet was written in stratum order, so a labeller could infer flag status from row position. It is superseded and was never given to anyone (kept, renamed `.SUPERSEDED-never-labelled`).
   `make_sheet.py` writes `sample200_sheet_v2.tsv`: rows shuffled with a separate recorded seed (20260936), columns n / id / claimed language / start_s / end_s / text / label. **No engine, flag, score or reason.** The id -> cell/flag key is a separate box-only file (`sample200_key_v2.json`), joined only after labelling.
2. **Label set (five).** readable | **romanised_readable** | garbled | wrong_language | unsure. `romanised_readable` = an Indic language written in Latin letters that a fluent reader can follow. It is reported separately per cell: on `sravaani/und` (4,220 of the 5,352 flags) it IS the flag's precision.
3. **Estimator.** A flagged row is a TRUE positive iff labelled garbled or wrong_language; readable and romanised_readable are false positives (the line would be hidden from a reader who could read it); unsure is excluded and bounded both ways. Per-cell counts first, then the weighted overall figures of `sample_draw.py`. Precision is reported FIRST.
4. **Precision floor before anything hides (pre-registered).** A cell's flag may collapse lines by default in the consult view only if, over that cell's labelled flagged rows (n >= 10), the true-positive share is >= 0.80 AND romanised_readable is <= 0.20 of them. Otherwise that cell is annotate-only (a visible pill, never collapsed). Recall is reported, not gated. Until labels exist NOTHING is written to the vault as a readability annotation.
5. **Re-run is not self-judged (337c part 2).** indic-mt keeps BOTH outputs and their scores per segment; the readability score may pre-sort, but `better` is decided from a blind before/after sample that V/Sandhya judge without knowing which is which. Until that judgement exists a re-transcription record carries `better: null`.
6. **Labellers.** V or Sandhya only (no model reader on real text, ruling 42/306), blind to the flag, before any number is posted.
