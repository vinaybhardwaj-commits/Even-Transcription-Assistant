## A1. The route split is nearly moot, and the P0 key finding changed
P0 (`SCHEMA.md` section 3) measured the deterministic key as absent before 11 Aug and complete from 14 Aug (eta-refuter-2 reproduced this at about 16:07). Stage A of the builder at 17:12 resolved the key for **6,691 of 6,713 visits (99.7%) across the whole window**, and the exact P0 probe on 3 Aug now returns 135 of 135 (it returned 0 of 135). The service-request rows for 1-3 Aug were loaded to the warehouse on 2-4 Aug, so they were not late arrivals; my P0 probe did not record whether the queue-side `SERVICE_REQUEST_UID` was empty or merely unresolved on those days, and the queue metadata carries repair-backfill markers, so a queue-side repair is the likeliest cause, **unverified**. Consequence: the KEY / HEUR split in v1 is kept, but HEUR now covers 22 visits. `SCHEMA.md` gets a dated note; its earlier numbers stay as what was measured then.

## A2. Ruling 163: `offered_in_house` per procedure type (decided before seeing the referred-out list, refined after)
- **In-house corpus** (24 Mar to 24 Sep 2026, six months): OT-note `surgery_name` (899 rows over the six months) plus procedure billing lines (`IP Package`, and `Surgery` lines whose item name is not overhead). Admissions carry no procedure name, so they add nothing to a type. **Limit: the corpus is OT and inpatient billing, so an OPD-only procedure (a chemical peel, a nail excision, a nebulisation) has zero occurrences whether or not it is done here.** Ruling 163's rule is applied as written; the list below marks that limit.
- **Unit:** the advised procedure name (structured array, `surgery_or_procedure.name`), not a type key. Status per name: `IN_HOUSE` if any distinctive stem (the first 6 letters of a content word of 6 or more letters, excluding a fixed list of generic surgical words) occurs in the corpus; `REFERRED_OUT` if it has at least one distinctive stem and none occurs; `UNJUDGED` if it has no distinctive stem. CT angiography is `REFERRED_OUT` by V's ruling whatever the corpus says.
- **Rx level:** `REFERRED_OUT_ONLY` (every named entry referred out) is dropped from N1; `UNNAMED` (no named entry, 100 of 518) and `UNJUDGED` stay in N1 and are flagged.
- **What was decided when (disclosure).** The first version keyed types on procedure-suffix words (-ectomy, -plasty ...). It was replaced because (a) it parsed each name as a stringified object (a bug in my extraction; fixed) and (b) an exact type key gave zero counts for names spelled differently in the corpus, so half its "zero" types had in-house occurrences under a stem check. The stem check was designed from the advised-name list and the corpus counts, not from outcomes, but the pool recount of the first run (116 to 114) was printed in the same output; the recount moves by at most a few prescriptions under either method.
- **CT angiography and the pool:** 30 CT-angiography prescriptions in the window; **1** was in the structured-flag set (and it is excluded from N1 and from the done labels); the other 29 were in neither flag set and were never in the pool.

## A3. Ruling 164: plain CT is a procedure proposal; a new done source
- **Advised:** an order on the Rx for a CT scan that is not a CT angiography (`further_investigation`, matched on `investigation__uid`, same master as the CT-angio match). New advised class `ADV_CT`, reported apart from `S` and `P`. MRI, X-ray and echo stay out (ruling 84).
- **Done source `RAD`:** a radiology order or bill for the same patient within [-1, +30] days of the Rx (ruling 164). The tables and the join key come from `mb-rx`; I add the source to the builder when they are named. **Until then no plain-CT Rx can be labelled done or negative.** CT angiography is still advised-only, referred out, never a negative (ruling 163).
- The hospital does CT in-house (ruling 163), so a plain-CT Rx with no order or bill within the window is a legitimate candidate negative, subject to the same maturity rule and the same censoring caveat as N1.

## A4. Visits that never went through the queue (decided after looking at the positives, disclosed)
Of the 78 mature done-positives (30-day window), only 35 have a queue visit with a clean link. The other 43 are hospital GP (29) and gynaecology (14) prescriptions; their consult id resolves to a `CONSULTATION` service request in 42 of 42 cases, but only 3 of the 42 requests appear on any queue step. So they are consults that did not go through the queue.
- **New route `RXWIN`:** for an advised or sampled Rx with no queue step, the visit window is the Rx's own `[timestamp, updated_at]` (median 6.8 min for hospital GP, 11.8 min for GP; if `updated_at` is missing, `timestamp` plus 8 minutes). Tier B for tier purposes, reported as its own route. P0 showed the Rx window agrees with the queue window to seconds where both exist, but it is a software window, not a door-to-door one (SCHEMA.md section 4).
- **What does not change:** v1's margin rule, floors, doctor-day decoy rule and the circularity rule apply to `RXWIN` visits identically. The decoy set for an `RXWIN` visit is the same doctor's other same-day visits from either route.
- Reporting adds `RXWIN` beside `KEY` and `HEUR` in every table.
