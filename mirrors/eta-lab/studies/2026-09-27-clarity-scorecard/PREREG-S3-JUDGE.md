## Label rule (C1, one rule)
- The label is the language the speakers MAINLY use: en hi kn ta te ml. English drug names, doses, diagnoses, test names and other English medical words inside a sentence in another language do NOT make the clip mixed (a Hindi consult that names "amlodipine 5 mg" is `hi`).
- `mixed` = the speakers keep switching between two of these languages at sentence or clause level. `none` = no speech.
- SELFTEST truth: the event's MAIN language: an event tagged xx-en (the code-mixed dialogues, e.g. Hindi sentences with English drug/test words) is `xx`, NOT mixed; `mixed` only when the events' main languages differ; `none` for silence/tones. Only events starting inside the judged (cut) part count (C4). (Disclosure: I first wrote xx-en = mixed, saw in the smoke run that the judge says hi/kn for them, read the invented texts, and saw they are intra-sentence Hinglish/Kanglish, so under the C1 rule they are hi/kn. The rule itself was fixed before any clinical-suite run.)
- Consequence for S3 (router-fix must pre-register it, C1 second half): how a judge label maps to a right/wrong route path. My proposal for router-fix: a route to language L is RIGHT when the judge says L; when the judge says `mixed`, a route to either of the two component languages is right only if router-fix names both components (hi-en, kn-en); `none` windows are excluded from wrong_pct and counted separately.

Accuracy, Wilson 95% lower bound and the confusion pairs are reported per label and per condition. The clinical suite for the gate is diar-lab's W33.1 suite (8 dialogues x en hi kn ta te ml + 8 x hi-en, kn-en, three variants each); the validation runs on the WHOLE suite, once per prompt sha; no prompt edit after a validation run unless a new run and sha are declared.

## Stated LIMIT of the v3 validation (eta-refuter-2 #4239; written before the v3 run)
confirm3's babble is always about 5 dB BELOW the dialogue (SNR 5), so "the foreground is the closest/loudest speech" is true by construction. In a real room the desk/ceiling microphone can be as near to chatter at the door as to the doctor, and the background can be as loud as the consult. A v3 pass therefore validates "QUIETER background speech is ignored", NOT "any background is ignored". The S3 scorecard entry will say so ("validated for background >= 5 dB below the consult"). A diagnostic 0 dB babble cell (not part of the gate, not scored toward `usable`) is requested from diar-lab if cheap; it shows where v3 breaks and is reported separately.

### Correction (eta-refuter-2 #4373, same 27 Sep, BEFORE any v4 run): switch definition fixed to match the suite's mixed truth
As first declared above, S's definition said "within their own turns", which diar-lab's `clinical.build_mixed` (main `486ea95c`) does not produce: it alternates the matrix language PER TURN (turn 1 base language, turn 2 English, ...), so every individual turn is monolingual and the real switch happens ACROSS a speaker's consecutive turns, not within one turn. A model following the original wording literally would answer S=false on every truly-mixed suite item, which would make v4 fail by correctly obeying a wrong instruction rather than by any real judge weakness.
FIX (option (a) from #4373, the cheaper one and closer to how real clinics actually code-switch): S's definition is changed to "from one sentence or clause to the next, WITHIN a turn OR across their own consecutive turns", with an example added to the prompt (one speaker's Hindi turn followed by an English turn, or a language change mid-turn). No other part of v4 changes. New PROMPT_SHA pinned in code (see lang_judge.py; not restated here to avoid a stale copy — read it from the file). Corrected before any v4 run: no judged.jsonl exists under either the pre- or post-fix sha. eta-refuter-2 PASSed the fix, independently re-derived (#4379).

STATED IMPLICATION of the fix (eta-refuter-2 #4379, not a blocker, written before any v4 run): because the prompt's example names "the other speaker's turn in English", a real consult where the doctor speaks English and the patient speaks Hindi (two DIFFERENT foreground speakers, each consistently monolingual, never switching within themselves) now scores `mixed` under v4, same as a single speaker who code-switches. This is consistent with v4's own rule (switching between two of the six languages across the foreground speakers' consecutive turns) and is not a defect, but it means v4's `mixed` label conflates "one bilingual speaker switching" with "two monolingual speakers using different languages" — read S2/real-audio `mixed` results with this in mind; it is a scope decision inherited from the switch definition, not a bug to fix in v4.
