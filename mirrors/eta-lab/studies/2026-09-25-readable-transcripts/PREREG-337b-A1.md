## A1.1 Output (replaces T3)
- Files: `~/eta-data/lab-vault/staged/annotations/translation/<room_id>/<ist_date>/<YYYYMMDDHHMM>-linker.json` (dirs 0700, files 0600), one NEW file per flush and room-day, never overwritten (if the name exists the next minute is used, so later timestamps still win per (k, i)). The IST minute (+05:30) is the name's time.
- Body: `schema` `eta-lab-annotation/1`; `kind` `translation`; `provenance` {`producer` `linker`, `model` (as returned), `provider` (as returned; a list only if calls disagree, which fails the window), `zdr` true, `created_at` ISO +05:30, `prompt_sha256`, `script_commit`}; `records`: {k: sha256 of that run record file}; `items`: a list of `{k, i, src_sha256, q, en}` where `k` is the window key without the leading `runs/` and the trailing `.json`, `i` the segment index in the record's segments list, `src_sha256` the sha256 of the exact native segment text (utf-8 as stored), `q` the model's flag (`ok`, `garbled`, `untranslatable`) and `en` the English (kept for every returned line, whatever its `q`). **A failed line or window is an item `{k, i, src_sha256, q: "mt_failed", err}`** with `err` from the closed list `isolated_line_failed`, `route_mismatch`, `http_failed`, `malformed_twice`, `retries_exhausted`, `all_lines_failed` (no text, no `en`).
- **Not written by this script:** the vault push (lab-viewer's uploader does it), the run records, the index, the native text. Windows with no `room_id` (parity clips) are skipped and counted.
- **Held for Fable's OK:** annotations/ is a new vault key kind (refuter-2 #1907 point 5). Until Fable says OK via the conductor, files stay in the staged directory and the uploader must not push them; no real call is made before that OK stands, so that no translated text is produced with nowhere approved to go.

## A1.2 Resume (replaces T4's sidecar rule)
The annotation files are the state. Read all `*-linker.json` files under `annotations/translation/`, in file-name order; the last item per (k, i) wins. A segment is **done** iff its last item has `en` (not `err`) and its `src_sha256` equals the sha256 of the segment's current text. A run translates only the not-done in-scope segments, newest date first as in T4; failed items are retried by the next run and win by timestamp. Items are flushed every 10 windows and at the end of the run, grouped by room-day. Hourly counts come from these files (`report`).
