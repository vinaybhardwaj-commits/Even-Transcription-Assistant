# REPORT alert-relay v3 (consult-audio, 8 Oct 2026). Repo ~/oc/consult/alert-relay. Fixes REFUTE-v2.md (FAIL, 1 MEDIUM + LOWs). Nothing installed or enabled, nothing posted to the real bus.
v3 keeps v2 (idempotency key + [retry N], dead letter, UTF-16 subject cap, identity by ssh alias, state reset to the end, unit condition) and v1 (offset/inode/tail fingerprint, rotation, truncation, partial line, malformed lines, dry-run default). 57 tests pass (`/usr/bin/python3 -m unittest discover -s tests`), 12 new.
- **M2 inverted:** permanent (dead-letter, move on) ONLY for the bus's own validation texts: "subject exceeds", "control characters", "body exceeds", "looks like it contains a secret", '"to" must be', "no recipients resolved". Every other isError / JSON-RPC error (herdr agent list timeout, "database is locked", identity unresolved, any unknown text) and every transport failure is transient: retry with backoff and the [retry N] mark, the offset holds, nothing is dead-lettered. So a wrong forced command at go-live shows as "bus down" in the log and loses no alert. Tested per text against the fake MCP bus, and with a bus that is "locked" twice then accepts.
- **L-b:** `load_state` now validates `inflight` (dict; int tries / end, str sha), `notice` (dict of two strings) and `head` (str). A wrong type resets like a corrupt state (start at the end, one "relay state reset" alert) instead of raising on every poll.
- **L-c:** a reset (or `start: end`) begins at the offset just after the last newline, so a line still being written is forwarded whole once it completes, never as a fragment. A saved offset that is not at a line start skips forward to the next newline (logged).
- **L-d:** a spool replaced by a copy (new inode, the same bytes up to the offset: editor save or cp + mv) keeps the offset and re-sends nothing. A genuinely new, different file still starts at 0. The reset notice keeps its retry count across a crash (same key, `[retry 1]`).
- **Bad config:** a config that does not parse, is not an object, or has no recipients logs `CONFIG ERROR` and exits 78 once; the unit has `RestartPreventExitStatus=78` (and the ConditionPathExists for a missing file), so no crash loop.
- **L-a (docs):** `ssh-config.example` no longer claims POST_TO_ALLOW works for this key (only ssh-forced-postonly.sh reads it); it adds `from="127.0.0.1,::1"` and says the key gets the full non-orchestrator bus surface unless the server gets an allowlist. For fable.
- **Not changed:** L2 (a spool replaced with mv loses the old file's unread tail when no .1 exists; logged).
