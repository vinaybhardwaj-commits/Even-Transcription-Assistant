# Chain Check (P2, ruling 122 / SURGICAL-CHAIN-LINKER.md)

Raters check the linker's chains: one prescription, what happened afterwards, and the recording of one visit. V + Sandhya,
PHI-cleared; the Rx text is shown RAW (ruling 122). No linker verdict, link score, class or tier is ever shown.
`page.html` is generated by `build_page.py` from the surgery page's tested blocks (CSS, transcript, audio player,
Range probe + Blob fallback) plus the chain-specific code; publish `page.html`.

## Screen
Prescription (raw text, written-at and author) -> "What happened later" (booking / OT note / discharge as label/value rows)
-> three blind questions -> sticky audio player + the visit transcript (tap a time stamp to hear from there; greyed and
folded turns outside the consult as on the surgery page).
1. Is this recording the visit that produced this prescription? Yes / No / Not sure.
2. (Yes or Not sure) Is the operation that was later done discussed in the conversation? Yes / No.
3. (Yes to 2) Was it proposed in this visit, or earlier? In this visit / Earlier, not in this visit / Not proposed at all.
A chain is done when the visible questions are answered ("No" to 1 ends it). Optional note. Autosave to `checks/<rater id>`.

## Chain doc contract (the linker's P1 output is converted to exactly this)
db collection `chains`, one doc per chain, doc id = the id (opaque; nothing about the class in it):

    {"id":"c9Km2q","date":"2026-09-23",
     "rx":{"text":"<raw Rx text>","created_at":"2026-09-23 11:42","author":"Dr X"},
     "facts":[{"label":"OT booking","value":"..."},{"label":"OT note","value":"..."},{"label":"Discharge","value":"..."}],
     "encounter":{"start_s":0,"end_s":80},
     "audio_full":{"src":"audio/c9Km2q/full.mp3","t0_s":0,"duration_s":82},
     "turns":[{"i":0,"start_s":2,"end_s":6,"speaker":"doctor","lang":"en","orig":"...","en":"...","outside":false,"earlier":false}, ...]}

`turns` has the same shape as the surgery consult docs (0-based `i`, `start_s`/`end_s` on the clip clock, `outside`/`earlier`
flags for talk before or after the consult, `earlier` folds it). `audio_full` is MP3 or MP4, served as a page file at that
path (the page probes Range support and falls back to a Blob URL for iOS). **No other field**: no linker verdict, link score,
candidate rank, class, tier, Jev answers. The page keeps only the fields above, but anything else in a doc is readable in the db.
Check before seeding:

    python3 check_chains.py <dir> --expect N      # dir/chains/*.json + dir/<audio paths>

## Capabilities and db rules (for the publish)
`db` and `user` (`user` with scopes `["profile"]`).

    { path: "chains", read: "view",     write: "admin" }
    { path: "checks", read: "interact", write: "interact" }

Owner tab **Results**: totals per question and each rater's answers per chain, and whether two raters agree on "same visit".
