# eta-presence-guard

Keeps the Pulse Presence Chrome extension force-installed on the EHRC kiosk Macs.

**Problem.** The extension is force-installed through a hand-written
`/Library/Managed Preferences/com.google.Chrome.plist`. macOS wipes that directory at boot, so
Chrome silently uninstalls the extension. **Fix.** A root launchd daemon re-asserts the
`ExtensionInstallForcelist` entry every 60 s, reports every non-ok action to
`https://www.evenscribe.app/api/presence`, and (last resort, any hour, console idle) restarts Chrome so it re-reads policy.

Extension: `choegfgddhpljibnolbcljnlfhfpimbh`. Entry written:
`choegfgddhpljibnolbcljnlfhfpimbh;https://www.evenscribe.app/ext/<MACHINE_ID>/update.xml`.

## Files

| File | Installed to |
|---|---|
| `eta-presence-guard.sh` | `/usr/local/libexec/eta-presence-guard.sh` (0755 root:wheel) |
| `com.eta.presence-guard.plist` | `/Library/LaunchDaemons/com.eta.presence-guard.plist` (0644 root:wheel) |
| (generated by `install.sh`) | `/usr/local/etc/eta-presence-guard.env` (0600 root:wheel: `MACHINE_ID`, `INGEST_TOKEN`) |

Log: `/var/log/eta-presence-guard.log`. State: `/var/db/eta-presence-guard/` (`last_rewrite`,
`last_relaunch`, `ok_count`; epoch seconds).

## Install (on the kiosk, as root)

```bash
printf '%s\n' "$INGEST_TOKEN" | sudo bash install.sh --machine-id EHRC-ECHOs-Mac-mini
```

Idempotent. Refuses an id outside the hard-coded list. After `bootout` it waits (max 10 s) for the
service to disappear, then retries `bootstrap` up to 3 times, 2 s apart. On a terminal the token is
prompted silently (`read -rs`). Token comes from stdin only; it is never
echoed or placed on argv. Known ids: EHRC-AUDIOMETRYs-Mac-mini, EHRC-CONSUL2s-Mac-mini-2,
EHRC-CONSUL4s-Mac-mini, EHRC-CONSUL4s-Mac-mini-2, EHRC-CONSUL5s-Mac-mini, EHRC-CONSUL6s-Mac-mini,
EHRC-CONSUL7s-Mac-mini, EHRC-DISCUSSIONs-Mac-mini, EHRC-ECHOs-Mac-mini.

## Uninstall

```bash
sudo launchctl bootout system/com.eta.presence-guard
sudo rm -f /Library/LaunchDaemons/com.eta.presence-guard.plist /usr/local/libexec/eta-presence-guard.sh \
           /usr/local/etc/eta-presence-guard.env
sudo rm -rf /var/db/eta-presence-guard
```

## Behaviour per tick

1. Unknown machine id: log `unknown_host`, exit 0, write nothing.
2. Plist absent -> `missing`; present without the entry -> `stripped`; either within 180 s of
   boot -> `boot`; else `ok`. A rewrite is atomic: it copies the plist to a temp file in the same
   directory, rebuilds `ExtensionInstallForcelist` in one PlistBuddy call as every existing
   entry whose extension id (text before `;`) is not ours, then ours appended, lints the temp file,
   sets root:wheel 644, `mv -f` into place, and only then runs `killall cfprefsd`. Any failure
   leaves the original untouched and logs `rewrite_failed`. Other keys are preserved. A corrupt
   plist is replaced. `ok` writes nothing, kills nothing, and logs once per 30 runs.
3. Boot race: the RunAtLoad tick can run before macOS regenerates `/Library/Managed Preferences`
   (~7 s after boot) and wipe the file. While uptime < 300 s the script keeps re-checking every
   10 s (after the normal check), rewriting if the entry disappears, and stops after 2 consecutive
   checks with the entry present, at uptime 300 s, or after 40 checks. It always exits.
4. Relaunch rung. Ruling (V, 5 Oct): Chrome restart is allowed at any hour when the extension is
   missing after a rewrite and the console is idle > 10 min. Field finding (Audiometry, 5 Oct,
   17:09-17:19): after the policy file was restored Chrome did not reinstall the extension for
   9+ min; `open -a "Google Chrome"` on a running Chrome does not reload policy, a quit + relaunch
   did (49 s). All must hold: last rewrite >= 3 min ago; the extension is MISSING (see below); this rewrite has not already been consumed by a relaunch
   (at most one per rewrite, tracked in `last_relaunch_rewrite`); HIDIdleTime > 600 s; no relaunch
   in 30 min. There is no time-of-day gate. Action: `pkill -TERM -x "Google Chrome"` (graceful quit,
   session restore keeps tabs), wait up to 15 s for `pgrep -x "Google Chrome"` to be empty,
   `pkill -KILL -x "Google Chrome"` only if it is still running, then, as the console user via
   `launchctl asuser`, `open -a "Google Chrome" https://pulse.even.in/`. If Chrome was not running it
   is only opened. Logged as `relaunch method=<term|kill|open>`. No osascript: it can raise an
   Automation consent dialog on the kiosk screen. Never touches profiles beyond testing that the
   extension directory exists.

   **How "missing" is decided.** The guard asks Chrome which profiles are open: it reads only
   `profile.last_active_profiles` (else `profile.last_used`) from the console user's
   `Chrome/Local State` with `plutil -extract`, and nothing else from that file. Names containing `/`
   or equal to `.`/`..`, and names with no directory on disk, are dropped. If that yields at least one
   profile (`basis=active`), the extension counts as present only when EVERY listed profile has
   `Extensions/<id>/` with at least one version subdirectory; one profile lacking it is enough to
   proceed (`extension_present_active` when all have it). Stale closed profiles that still hold an old
   copy no longer mask the gap (OPD 4, 5 Oct). If Local State is absent, unreadable, malformed or
   names no existing profile (`basis=fallback`), the old rule applies: present when ANY profile of the
   user has the extension directory (`extension_present`). The dry-run and `relaunch method=...` log
   lines carry `basis=`, `profiles=` and `missing=`.
5. Every non-ok action POSTs `{"events":[{"source":"guard",...}]}`, 10 s timeout, token passed
   to curl on stdin. Post failures never fail the tick.

`rewrite_failed` posts are capped at 3 per boot (then `post status=suppressed`).

Log lines: `<ISO8601 IST> rewrite reason=<r> machine=<id>`, `ok`, `relaunch`, `unknown_host`,
`post status=<http code>`.

## Deviation from the spec: KeepAlive

The spec asked for `KeepAlive true` with `StartInterval 60`. The script is short-lived, so an
unconditional KeepAlive makes launchd respawn it in a tight loop (throttled to 10 s, but still
wrong, and it would double the 60 s cadence). The plist uses `StartInterval 60` + `RunAtLoad true`
and `KeepAlive = {SuccessfulExit: false}`: launchd respawns it only if a tick exits non-zero. The
script always exits 0, so that clause is a crash-only safety net.

## Test (no root)

```bash
bash test.sh          # prints PASS/FAIL per case and a final SUMMARY line
NO_KILL=1 PLIST_PATH=/tmp/x.plist STATE_DIR=/tmp/xs MACHINE_ID=EHRC-ECHOs-Mac-mini \
  bash eta-presence-guard.sh --dry-run
```

Test hooks: `PLIST_PATH`, `STATE_DIR`, `ENV_FILE`, `MACHINE_ID`, `NO_KILL=1` (skips killall, curl
and the Chrome launch), `UPTIME_OVERRIDE=<seconds>`, `BOOTTIME_OVERRIDE=<kern.boottime text>`, `CONSOLE_USER_OVERRIDE`, `HOME_ROOT`,
`HID_IDLE_OVERRIDE`, `BOOT_LOOP_SLEEP`, `QUIT_POLL`, `PB`; `install.sh` takes `INSTALL_ROOT` (sandbox prefix; also skips every launchctl call unless
`LAUNCHCTL=<stub binary>` is given), `--dry-run` (prints decision and the exact
action; writes, posts and kills nothing). The relaunch rung (gates and the open/term/kill methods, against stub `pgrep`/`launchctl`/`pkill`)
and the boot loop (including a simulated wipe) are exercised in test.sh through the override hooks above;
`install.sh` is tested against a stub `launchctl`.
